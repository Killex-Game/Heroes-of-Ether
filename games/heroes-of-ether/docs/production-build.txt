Две версии игрового кода

Исходники в репозитории предназначены разработчикам и сохраняют комментарии.
Для VPS создаётся отдельный каталог сборки. Редактировать его вручную не нужно:
следующий выпуск собирается заново из конкретной проверенной версии исходников.

Из games/heroes-of-ether:
  npm ci
  node scripts/deployment/build-production.cjs ABSOLUTE_NEW_DIRECTORY

В новом каталоге:
  npm ci --omit=dev --ignore-scripts

Снова из исходной игры:
  node scripts/deployment/finalize-production.cjs ABSOLUTE_NEW_DIRECTORY

Каталог назначения должен быть новым. Сборщик отказывается писать поверх
исходников и существующего каталога. В него входят игровые файлы, публичная
графика, базовая конфигурация и необходимые инструменты эксплуатации.
Сохранения, приватная конфигурация, секреты, тесты и документация разработчиков
в сборку не копируются. Реальные настройки сервера сохраняются отдельно при
развёртывании и не заменяются значениями примеров.

JavaScript обрабатывается Acorn: комментарии заменяются пробелами с сохранением
переводов строк, границ токенов и автоматической расстановки точек с запятой.
Дерево программы до и после должно точно совпасть. Строки, регулярные выражения
и адреса не очищаются поиском по тексту. Hashbang остаётся командой интерпретатора.
CSS обрабатывается css-tree, HTML и SVG через parse5. Встроенный код проверяется
отдельно. Карты исходников в сборку не включаются.

После установки только рабочих зависимостей finalize-production очищает
исполняемый JavaScript зависимостей и проверяет равенство его дерева программы.
TypeScript и sourcemap удаляются только внутри нового node_modules сборки.
Лицензии сохраняются, извлечённые уведомления о правах вынесены в отдельный
THIRD_PARTY_NOTICES.txt. Лицензии не являются исполняемым кодом.

production-manifest.json связывает каждый исходный файл с SHA256 собранного.
dependency-manifest.json фиксирует рабочие зависимости после обработки.
Хеши обязательны при загрузке и проверке опубликованных файлов. Версия Git
в манифесте сама по себе не доказывает чистоту рабочего дерева: для выпуска
нужны сохранённый commit и проверка всех sourceSha256.

Проверки выпуска включают штатные тесты затронутой логики, запуск собранного
сервера и браузерные проверки собранных публичных файлов. Удаление комментариев
не заменяет эти проверки и не доказывает отсутствие всех секретов.

Независимая админка развёртывается отдельным выпуском. Обновление игрового
процесса не даёт права удалять её закреплённый release или останавливать её.
