Прототип удерживает закрытый базовый checkpoint и нужные sealedWAL
через hardlink. Журнал перед checkpoint сохраняет именно тот наборсегментов,
который передаёт рабочему потоку. Позже появившийся stagedбустер не попадает
в преждевременную очистку. Каждый PGчитатель получает отдельный неизменяемый
набор ссылок. Новые WAL применяются с прежней проверкой checksum/ревизий.

Окно ограничено16MiB WAL,2048сегментами и5минутами; при превышении илиошибке
ссылки окна снимаются, следующий pin использует обычную полную базу.
Существующие читатели имеют собственные ссылки и не теряют данные.
Основные checkpoint/WAL остаются единственным источником восстановления.
Лимит16MiB относится только к WAL. Старый полный checkpoint тоже удерживается
ссылкой после атомарной замены текущего: его размер нужно отдельно учитывать
в дисковом резерве. Активные читатели могут временно удерживать прежнюю базу
после сброса окна. Это не16MiB-предел общего использования диска или RAM.
Window освобождается при close, послеаварийные flatдиректории чистятся
существующим startup-контролем только после получения exclusivewriter.
Опция readWindow:false оставляет прежний путь для контрольных измерений.
