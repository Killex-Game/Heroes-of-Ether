Кандидат SnapshotBuilder
Каждый раз вычисляет SHA-256 текущего содержимого записи, затем повторно
использует канонические байты и хеши только при точном совпадении.
Изменённая запись проходит прежнюю упаковку и разбиение на фрагменты.
В памяти кеша хранятся Buffer, а не второй большой граф объектов.
Полный хеш мира вычисляется потоком тех же канонических байтов.
PostgreSQL получает прежний формат. Период записи, WAL, fsync, lease,
квитанции, история, проверка холодного старта и резервные копии сохраняются.
Это промежуточное снижение повторной работы. Адресный ProfileRepository,
отделение истории и ограниченный кеш активных профилей ещё не реализованы.

Воспроизведение нагрузочного теста коллегами
Из каталога games/heroes-of-ether на изолированном Linux-стенде:
node scripts/benchmarks/postgresql-capacity.cjs PRIVATE_CONFIG NEW_OUTPUT 1
Последний аргумент: 1/2/3 комнаты, то есть 35/70/105 клиентов арены.
NEW_OUTPUT должен быть новым каталогом вне Git. Конфигурация PostgreSQL
сохраняется там с правами 0600, каталог с правами 0700. Не публиковать его.
Скрипт сбрасывает унаследованные LOAD_* флаги, включает incrementalSettlement,
создаёт собственную случайную схему, сверяет PG и все ACK с восстановленным
WAL и лишь после обеих сверок удаляет только эту тестовую схему.
Для сопоставимых результатов ограничивать весь тест одной cgroup:
CPUQuota=300%, MemoryMax=3G, Nice=10. На рабочем VPS запускать только под
контролем его очередей, PG, диска и задержек с остановкой теста при ухудшении.
Короткие критерии capacity-assessment допускают 19 Гц и action p95 до 500 мс;
предпочтительный p95 работы такта ниже 25 мс оценивается отдельно в JSON.
