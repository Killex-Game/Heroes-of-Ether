# Подготовка следующего ивента

Общие проверки автоматизированы, но один успешный набор тестов не гарантирует отсутствие ошибок в ещё не написанном событии. Для каждого нового набора нужны проверки его конкретных наград, действий и интерфейса, затем сравнение нагрузки на VPS. Подготовка не запускает событие у тестировщиков.

## Регрессии перед выпуском

`npm run test:events` проверяет все установленные наборы. `--pack=<contentPack>` выбирает один набор вместе с общими сценариями и рулеткой. Новый `contentPack` без собственных сценариев отклоняется проверкой `event-release-coverage.test.js`. Обновления тестов существующего события автоматически включаются по его зарегистрированным префиксам. Все эти тесты входят и в полный набор игры.

| Риск | Где проверяется |
| --- | --- |
| Рулетка открылась без своих достижений | `event-roulette-companions`, `lucky-week-arena`, `lucky-week` |
| Доступ до начала, после конца, отмена будущего запуска, продление | `event-manager`, `event-timing`, `event-lifecycle-cache` |
| Повтор наград после запроса, перезапуска или отказа записи | `event-manager`, `black-friday-recovery`, `black-friday-prize-receipts` |
| Неверный множитель купона, валюты, сундука или рулетки | `black-friday-economy`, `black-friday-chest-tokens`, `black-friday-expanded-chests`, `friday-roulette` |
| Смешивание дней, квот и запусков; повтор зачёта противника | `black-friday`, `black-friday-four-orders`, `black-friday-arena-orders`, `black-friday-order-balance` |
| Копирование всего архива заказов при каждом действии | `black-friday-progress-copy` и сравнение обработчика заказов |
| Перебор старых запусков при каждой проверке | `event-lifecycle-cache` и `scripts/benchmarks/event-lifecycle.cjs` |
| Пропущенные степени или награды в каталоге | `event-release-coverage` |

Это имена сценариев, а не утверждение, что любой будущий механизм покрывается ими автоматически. Если новый набор использует иную экономику, сундуки или прогресс, добавить соответствующие сценарии, включая восстановление подтверждённых операций после остановки процесса.

## Общая основа без лишней нагрузки

- `EventManager.active/scheduled` сохраняют результат до ближайшей границы запуска. Успешная административная запись заменяет снимок состояния и сбрасывает результат; неудачная запись оставляет прежний. Переход через начало/окончание и обратный ход времени проверяются без таймера.
- `event-run-lookup.findRunAt` используется обработчиками прогресса. Он учитывает время действия и досрочную остановку. Его нельзя заменять текущим `active()`: иначе запоздавшее подтверждение потеряет законный прогресс старого запуска.
- Кэшируются только результаты поиска в неизменяемом снимке расписания. Не кэшировать этим способом балансы, награды, заказы, множители аккаунтов или сутки игрока. Состояние расписания изменять через `EventManager.apply`, а не правкой полей сохранённого запуска на месте.
- Проверка доступа к рулетке не строит и не клонирует её публичное описание. Клиентские ответы по-прежнему независимы: их изменение не меняет серверные параметры.
- История наград и обязательные расчёты завершённых событий сохраняются. Не удалять их ради быстрого пути отключённого события.

## Условия нагрузочной проверки

На одной версии игры сравнить выключенный/включённый ивент с одинаковым сценарием. Измерить движение, деление, кормление, все бустеры, разную массу и число частей, а также действия лобби и конкретные обмены/заказы/награды. Указать реальных живых участников, отдельно генераторы нагрузки. Проверить 105 игроков, затем 350 и 700 по результатам предыдущего этапа. Для выпуска нужен непрерывный смешанный прогон не меньше часа на подтверждаемой нагрузке.

Сохранять p95/p99 успешных действий и задержек состояния, частоту тактов, очередь прогресса, CPU/RAM/GC и трафик, подготовку/разбор пакетов. Использовать диагностические пороги `capacity-assessment.cjs`; шумное сравнение повторять в обратном порядке. Микротест поиска ивента показывает стоимость только этого участка, не вместимость игры.

Проверить отдельно в браузерах: смену картинок вместе с заданием, индикаторы внутри окна, читаемость наград, размеры и отсутствие скачков, остановку скрытых анимаций и обработчиков. Реальный FPS не следует из серверного теста. Список существующих браузерных сценариев печатает `test:events -- --list`; для нового интерфейса расширить его.

В итоговом отчёте явно указать: выполненные и пропущенные проверки, результаты до/после, ограничения, версию кода и стенда. Не объявлять готовность по одному функциональному тесту или числу подключений. Найденная воспроизводимая регрессия блокирует рекомендацию релиза до исправления, но не отключает кнопки владельца.
