Карточка для регистрации

Название: Герои Эфира.
Тип: Игра.
Основной жанр: Аркада (рекомендация по механике, не утверждение о полном
перечне текущего кабинета). Дополнительный жанр, если предусмотрен: Экшен.
Описание жанра: многопользовательская фэнтези .io-арена с элементами RPG.
Краткое описание: «Сражайся на фэнтези-арене, усиливай героя и питомца,
объединяйся в кланы и участвуй в событиях!»
Расширенное описание: «Герои Эфира — многопользовательская арена в реальном
времени. Собирай эфир, поглощай соперников, разделяйся и используй бустеры.
Открывай персонажей и титулы, развивай питомцев, выполняй задания вместе
с кланом и участвуй в клановых битвах.»
Платформы: Web, мобильная версия сайта, мобильные приложения Android/iOS.
Возрастную маркировку не выдумывать: заполнить после проверки состава игры.

Регистрация владельцем

1. Войти своим аккаунтом VK в https://dev.vk.com/ → Приложения → Создать
   приложение. Выбрать «Игра», название и жанр; подтвердить создание в VK.
   Подтверждение аккаунта выполняет владелец; приложение ещё не создано.
2. Сохранить ID игры. Защищённый ключ хранить только на сервере, не в чате,
   HTML, Git или скриншотах. Код входа уже принимает ID как строку Int64.
3. Настройки → Другие площадки → Привязать OK ID. Создатель подтверждает
   свой аккаунт ОК и права разработчика. Дождаться появления ссылки ОК,
   записать vk_ok_app_id. vk_app_id остаётся ID связанной игры VK.
4. Сначала задать тестовый HTTPS-адрес в режиме разработки для всех трёх
   платформ. Действующая тестовая игра сейчас: https://195.208.123.221/.
   TLS этого адреса проверен без отключения проверки сертификата. Кандидат
   платформенного входа по этому адресу ещё не установлен. До включения
   для пользователей настроить выбранный постоянный адрес и все проверки ниже.
5. Добавить тестировщиков и права тестирования. Для платежей есть отдельный
   список тестировщиков в разделе «Платежи»; одного права администратора мало.
6. Заполнить описание, иконки, скриншоты, контакты поддержки, необходимые
   сведения о правообладателе и документы. Публичные страницы политики
   конфиденциальности/пользовательского соглашения в текущем public не найдены;
   данные владельца и условия нужно подготовить до подачи на модерацию.
7. Провести проверки входа/покупок через реальные оболочки VK и ОК, затем
   подавать отдельные заявки в каталог. Сейчас заявки не поданы.

Что реализовано в кандидате

VK Bridge 3.0.2 (MIT), локальная фиксированная копия с npm integrity и SHA256.
Сначала VKWebAppInit; при обычном открытии сайта SDK не загружается.
POST /api/platform/session проверяет подпись vk_*, приложение, площадку,
пользователя и время запуска. Срок принятия запуска 5 минут, допуск часов 30 с.
Проверка подписи не выполняется в игровом такте. Профиль открывается адресно,
новый профиль и привязка сохраняются вместе через существующий WAL.
Ключи идентичности: VK — vk_app_id + vk_user_id; ОК — vk_app_id + vk_ok_app_id
+ vk_ok_user_id. Привязка VK ID не меняет профиль ОК. Ники не участвуют во входе.
Собственный случайный билет на 12 часов передаётся в Authorization для API
и в WebSocket subprotocol для арены. Билет не возвращается выбранным
subprotocol, не помещается в URL и не становится cookie. На сервере хранится
хеш билета, таблица ограничена 10000 сессиями; это НЕ доказанная ёмкость игры.
Для перезагрузки iframe билет хранится в sessionStorage текущей вкладки.
При блокировке storage первый вход всё равно работает. При истечении билета,
перезапуске сервера или закрытии вкладки нужен повторный запуск из площадки.
Неисправная сессия не создаёт новый гостевой профиль. Админка остаётся закрыта
для iframe; ограничения origin для HTTP/WS остаются в силе.

Частные настройки и включение

config/social-platforms.example.json — шаблон. Рабочий файл только
data/social-platforms.local.json. enabled=false по умолчанию; без файла
существующий сайт работает по прежней схеме.
После создания приложения заполнить строковые vkAppId/okAppId, appSecret.
sessionSecret сгенерировать ОДИН РАЗ: 32 случайных байта в hex. Хранить его
в резервной копии вместе с данными. Это независимый ключ стабильной привязки,
его нельзя менять как ключ приложения: несовпадение останавливает вход,
не заводя пустой профиль поверх существующего. Для ротации нужен отдельный
миграционный инструмент; он сейчас не реализован.
requirePlatform=true запрещает гостевую регистрацию на платформенном стенде.
Не включать такой режим на действующем тестовом адресе до отдельного
подготовленного переключения: старым тестовым игрокам нужен прежний вход.
Для платформенного запуска проверить nginx: HTTPS/WSS, разрешённые iframe
VK/ОК, Referrer-Policy:no-referrer, журнал доступа без query/sign/Authorization
и Sec-WebSocket-Protocol. Админка сохраняет X-Frame-Options:DENY.
В коде кандидата no-referrer установлен; действующий nginx пока не изменён.

Платежи — отдельная незавершённая часть

Новые игры ОК поддерживают VKWebAppShowOrderBox. На сервере схемы callback
различаются: VK get_item/order_status_change; ОК get_item приходит на URL VK
с site=ok, подтверждение ОК — GET на отдельный URL. Указать в кабинете URL
можно лишь после реализации и проверки соответствующих обработчиков.
Планируемые адреса: /api/platform/payments/vk и /api/platform/payments/ok.
СЕЙЧАС ЭТИ МАРШРУТЫ НЕ РЕАЛИЗОВАНЫ. Не указывать их как рабочие и не включать
приём реальных оплат. В кандидате новые социальные профили не могут вызвать
тестовое начисление товаров или старую тестовую активацию VIP/Premium.

Нужно завершить: серверную фиксацию состава/цены заказа, проверку подписей
обоих видов уведомлений, отдельные цены в голосах и ОКах, подтверждённую
выдачу через WAL с учётом всех достижений/событий, неизменяемые квитанции
provider+transaction/order_id, повтор/отмену/устаревшую акцию/отказ записи.
Успех VK Bridge на клиенте не является доказательством начисления.
Старый пятиразовый лимит mock-покупок не переносить на настоящие платежи.
Сроковые VIP/Premium остаются разовыми покупками; подписки не добавлять без
отдельного решения владельца. Цена VIP остаётся 14 голосов.
Номинальное соответствие голосов ОКам не задано: цену ОК согласовать отдельно.

Приёмочные проверки после получения ID

Первый/повторный вход VK и ОК с ПК и мобильного клиента; смена устройства;
перезагрузка iframe; запрет cookies/storage; раздельные аккаунты одинаковых
ID; привязка VK ID у игрока ОК; выход/блокировка; reconnect арены; подделанный,
просроченный запуск; платежи официальными тестировщиками обоих провайдеров;
повтор callback после перезапуска, сбоя WAL/PG и смены цены пятничной акции.
Стендовые проверки подписи и браузера не заменяют эти реальные проверки.
До их завершения не объявлять игру готовой к каталогу и реальным оплатам.
