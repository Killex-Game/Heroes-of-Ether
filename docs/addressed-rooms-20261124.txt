Что реализовано
ProfileReader читает только заданные записи profiles и необходимые фрагменты
в одной транзакции REPEATABLE READ READ ONLY. Проверяет источник, поколение,
SHA-256, идентификатор игрока, размеры и количество запросов. Кеш ограничен
размером и количеством записей; возвращаемые объекты независимы от кеша.
Ключи расположения профилей поступают только из доверенного серверного индекса.
Адаптер не предоставляет прав записи и не снимает общую PostgreSQL lease.

В изолированном стенде каждая комната получает 30 выбранных профилей из БД,
а дочерний процесс получает проекцию полей симуляции. Кошельки, квитанции и
истории остаются у единственного владельца сохранений. Режим 35 мест доступен
только явно через ROOM_BENCH_ROOM_SIZE=35 для воспроизведения старых замеров.
Новая проверка SIGSTOP/SIGCONT задерживает только тестовый дочерний процесс.

Опциональный протокол sferorumiya-state-v9 упаковывает известные поля еды
в короткий массив с маской. Неизвестные расширения сохраняются в объекте.
Координаты рождения передаются точно, без дополнительного округления.
Кеши v8/v9 разделены; v8 остаётся протоколом по умолчанию, клиент рабочей игры
не переключён. WebSocket, частота тактов, физика, награды и графика прежние.

Ограничения и следующий обязательный этап
Главный обработчик пока держит полный мир. Индекс playerId -> storageKey
строится из этого мира; серверный поиск по playerId в БД ещё не реализован.
История не вынесена в отдельные таблицы. Выборочный читатель обслуживает
проверенный снимок PostgreSQL, а не заменяет актуального владельца профиля.
Обработка межпрофильных подарков, клановых границ, билетов входа, восстановления
владельца комнаты и работа на разных машинах должны быть завершены до включения.
Это отдельные процессы на одном VPS, не два независимых физических узла.
Маленький тест SIGSTOP подтверждает изоляцию физического цикла, не отказоустойчивость
всей экономики. Новых гарантий онлайна 300000 или стоимости такого онлайна нет.
