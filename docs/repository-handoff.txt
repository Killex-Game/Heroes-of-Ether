Цикл разработки и выпуска
1. В начале смены: git status, fetch, pull --ff-only при чистой рабочей ветке.
   Если ветка разошлась или есть чужие изменения — остановить автоматическое
   обновление и разобрать конкретный diff. Посменность уменьшает, но не
   устраняет риск: другая вкладка, агент или горячая правка могли изменить код.
2. Изменение в отдельной ветке, один понятный commit на законченную задачу.
   Проверки по затронутому поведению; полный прогон при выпуске серверных
   изменений. Зафиксировать отрицательные результаты и исправления фикстур.
3. Проверить индекс: node operations/scripts/check-repository.cjs [checkout].
   Проверка только читает индекс, не делает commit/push. Она ищет известные
   закрытые пути и признаки ключей, не гарантирует отсутствие всех секретов
   и не проверяет уже опубликованную историю Git.
4. Push и согласованное слияние. На VPS устанавливается конкретный проверенный
   commit/release, а не меняющаяся ветка. Не включать автоматический deploy
   любого push до появления проверенного процесса выпуска.
5. Собирать новый каталог релиза из предыдущего проверенного и передавать
   только изменённые файлы. Manifest: путь, старый/новый SHA256; для удаления
   отдельная явная запись. Не копировать data/config/secrets/admin-control.
   Переключать current только после сверки; сберегать независимую админку.
6. После проверки входа и PostgreSQL записать deployed commit SHA и release в
   краткую передачу смены. Код на VPS не редактировать отдельно от ветки;
   аварийную правку сначала сохранить diff и немедленно вернуть в Git.

Git не заменяет резервную копию
Рабочие профили, WAL, переписка, отзывы, TOTP/SSH/PostgreSQL credentials, состояние
админки и машинные конфигурации не публикуются даже в частном репозитории.
.gitignore дополнен в корне workspace и игры. Уже отслеживаемые файлы этим
не удаляются; после доступа требуется аудит индекса/истории. Runtime-ассеты
в public/assets входят в выпуск; исходные большие ZIP, node_modules и
скачанные Node runtimes — нет. Машинные настройки берутся из приватного
конфига, для коллег используются безопасные примеры.
